The transformer, assembled

The earlier parts built the pieces of a language model one at a time. This part puts them in order and follows six words through a whole model, from the word table at the bottom to the guess at the top. It turns out to be one simple block, repeated, and almost nothing but multiplication.

Built from the original papers (Vaswani and others 2017; He and others 2015; Ba and others 2016; Radford and others 2019; Kaplan and others 2020; Geva and others 2021), GPT-2’s published configuration and word list, and Meta’s Llama 3 report and code, facts checked against them · Read the source ↗

Part 1 turned tokens into lists of numbers, Part 2 turned scores into chances, Part 6 showed how the numbers are learned, and Part 7 let words look at words. The problem

Four pieces, but no machine yet

Earlier parts built the pieces one at a time: the table that turns tokens into lists of numbers (Part 1), scores turned into chances (Part 2), training that nudges numbers (Part 6) and attention (Part 7). This part bolts them together into the design nearly every chatbot uses: the transformer.

Three small pieces are new here: a feed-forward step, a running list that every step adds to, and a tidy-up called layer norm. None is hard. Together with attention they make one block, and a model is that block repeated.

The whole picture

One pass, from bottom to top

Here is the whole machine at work on Part 7’s sentence, “The boat drifted to the river”. Six tokens enter at the bottom. Each becomes a list of numbers, the lists climb through a stack of identical blocks, and at the top the last list turns into a chance for every possible next token.

One trip from bottom to top is a forward pass. Part 2 showed that writing one token takes one full pass public. The chances are made up for this page example; the shape of the machine is GPT-2 small’s, which has 12 blocks public. The rest of this part climbs the drawing one floor at a time.

Step 1

Look up each token’s row

In GPT-2’s list of 50,257 tokens, each word of our sentence is a single token with an ID number public. The first step looks up that ID’s row in the word table (Part 1, chapter 16). No arithmetic yet: just finding rows.

Each row holds 768 numbers in GPT-2 small, and 4,096 in Llama 3 8B, whose table has 128,256 rows public. Common words like “the” and “to” sit near the start of the list because they were glued together first (Part 1, chapter 5). From here on, every token is just its list.

Go deeper: where these IDs come from

The IDs are from GPT-2’s published word list (464 “The”, 8,848 “ boat”, 38,648 “ drifted”, 284 “ to”, 262 “ the”, 7,850 “ river”); the space in front of a word is part of its token public. Llama 3’s list is 128,000 ordinary pieces plus 256 reserved special tokens, which is where 128,256 comes from public.

Step 2

Mark where each token sits

The table hands “river” the same row wherever it appears, so order is lost (Part 1, chapter 18). GPT-2’s fix is a second table with one learned row per position, 1,024 of them public. The token’s row and its position’s row are added, number by number.

Newer models such as Llama 3 skip the position table. Instead, inside attention they turn each query and key by an angle that depends on position, the method called RoPE from Part 7, chapter 13 public. Either way, what climbs into the first block is one list per token that knows both what and where.

The analogy

A running list that every step adds to

Picture a notebook passed up a line of specialists. Each one reads it and writes a note in the margin; nobody erases. Each token carries its list up the model the same way, and every step adds a note to it.

Mapping it back: the notebook is the token’s list, often called the residual stream; each specialist is an attention or feed-forward step; a note is a list of the same length, added number by number. Where the analogy breaks: notes are numbers, not words, so a later note can cancel an earlier one, and the list never gets longer. It is 768 numbers at the bottom and 768 at the top.

The building block

One block: attention, then feed-forward

A block does two things to every token’s list, in order. First, attention: a tidied copy of the list gathers from earlier tokens (Part 7) and the result is added back. Then feed-forward: another tidied copy goes through a small network on its own, and that result is added back too.

That is the whole block. In Llama 3’s published code it is two lines: h = x + attention(norm(x)), then out = h + feed_forward(norm(h)) public. The “+” in each line is the running list from the last chapter.

Go deeper: attention’s four tables

Part 7 met the query, key and value tables. A block has a fourth, the output table, which turns the blended values of all the heads back into one note the length of the list. In GPT-2 small each of the four is 768 × 768, about 2.4 million learned numbers per block for attention public.

The new piece

Feed-forward: each token thinks alone

Attention mixes tokens together. Feed-forward does the opposite: it works on one token’s list at a time, never looking at its neighbours. The list is multiplied by a table that widens it four times, each number is bent, and a second table narrows it back.

The bend is what makes it more than a table: negative numbers are pushed to about zero, so each of the 3,072 middle numbers acts like a detector that is either off or firing by some amount. The 2017 paper used the simplest bend, ReLU, with a 512-number list widened to 2,048 public; GPT-2 uses a smoothed version called GELU public.

Go deeper: the formula feed-forward(x) = bend(x × table1 + b1) × table2 + b2

This is equation 2 of the 2017 paper, with ReLU as the bend public. In GPT-2 small table1 is 768 × 3,072 and table2 is 3,072 × 768: 4.7 million numbers per block, twice attention’s 2.4 million public.

The new piece

Feed-forward as a memory of patterns

What do the detectors detect? A 2021 study looked inside trained models and found that many feed-forward detectors fire on recognisable patterns in the text, and that what each one adds pushes up the scores of words likely to come next public.

So one useful picture is a huge memory of “when you see this, lean towards that”, with the detector as the question and table 2’s row as the stored answer. The same study found lower layers react to surface patterns and higher layers to meaning public. The three detectors drawn here are illustrations example; most real detectors are not this tidy.

The tidy-up

Layer norm: keep every list in range

Add notes block after block and some lists drift large or lopsided, which makes training unstable. So before each step a copy of the list is rescaled: subtract its average, divide by its typical spread, then apply two learned lists, a scale and a shift (Ba and others, 2016) public.

In GPT-2 and Llama 3 the norm tidies the copy going into each step, while the running list itself is left alone public. The 2017 paper did it the other way round, normalising after each addition public. Llama 3 uses a simpler variant, RMSNorm, that skips subtracting the average and only rescales public.

Go deeper: the numbers in the drawing

The twelve example numbers average 3.325 with a spread (standard deviation) of about 1.56. Each is turned into (number − 3.325) ÷ 1.56, so 6.1 becomes about 1.78 and 0.8 about −1.62 example. A real list has 768 or 4,096 numbers, and the learned scale and shift then stretch and move the result.

The wrong intuition

Why add notes instead of rewriting?

The obvious design would let each layer rewrite the list and hand it on. Deep stacks built that way train badly. In training, blame flows backwards through every layer (Part 6, chapter 9), and when each rewrite passes back only part of it, almost nothing reaches the early layers.

With the add-a-note design there is always a straight path from the top to every layer, so blame arrives undiminished. This shortcut, the residual connection, is how a 2015 image model trained networks 152 layers deep public, and the 2017 transformer put one around every attention and feed-forward step public. The halving here is an illustration example.

Stacking

Then repeat the block, again and again

A whole model is one block design repeated: 12 blocks in GPT-2 small, 32 in Llama 3 8B, 96 in GPT-3 and 126 in Llama 3 405B public. Every block has the same shape but its own learned numbers.

That is the surprise: the smallest and largest models here are the same plan, just wider lists and more blocks. Why making them bigger keeps working is Part 11. What changes from block to block is only what training put in the tables; as Part 7, chapter 12 showed, meanings sharpen as the lists climb.

The top

At the top: one list becomes every score

After the last block comes one more layer norm. Then the last token’s list is compared with every row of an output table using the multiply-and-add closeness score, giving one score per token (Part 2, chapter 3). Softmax turns scores into chances (chapter 4).

Only the last list is used to guess the next token. The other positions’ lists matter too: their keys and values were read by attention on the way up, and in training each position makes its own guess, so every word is a quiz (Part 6, chapter 12). These scores and chances are made up example.

Go deeper: one table used twice

The output table has the same shape as the word table: one row per token. GPT-2 simply reuses its word table here, as the 2017 paper did public. Llama 3 8B keeps a separate output table, another 525 million learned numbers public.

Where the numbers live

Count every learned number

Every learned number sits in one of these tables. Add them up for Llama 3 8B and you get 8,030,261,248, the “8B” in its name public. Attention is the famous part, but feed-forward tables hold 70% of the numbers.

Small models spend a big share on the word table, because 50,257 rows of 768 is a lot next to only 12 blocks. In big models the blocks dominate. A 2021 study put feed-forward at about two-thirds of a transformer’s numbers public; in GPT-2 it is exactly two-thirds of each block, and in Llama 3 8B, with smaller key and value tables and a wider feed-forward, 81%.

Go deeper: the exact count for GPT-2 small

Word table 50,257 × 768 = 38,597,376. Position table 1,024 × 768 = 786,432. Each block: attention 4 × 768² + 4 × 768 biases = 2,362,368; feed-forward 8 × 768² + 5 × 768 biases = 4,722,432; two norms 3,072. Twelve blocks, plus a final norm of 1,536: 124,439,808 in all public. The GPT-2 paper’s table lists this model as 117M; counting its published configuration gives the 124 million most software reports public.

A modern block

Llama 3’s block, drawn to scale

Llama 3 8B follows the same plan with newer parts public. Keys and values are shared by groups of four query heads (Part 7, chapter 15), so their tables are a quarter the size. Its feed-forward, called SwiGLU, uses three tables 14,336 wide.

In SwiGLU the “gate” table decides how much of the “up” table’s result gets through, then “down” narrows it back (Shazeer, 2020) public. Per block that is 41.9 million numbers for attention and 176.2 million for feed-forward, plus 8,192 for two RMSNorms. Llama 3 also drops the biases GPT-2 had public.

The cost

A pass is mostly multiply-and-add

Now count the arithmetic for one new token in Llama 3 8B, after 1,000 tokens of text. Each number in a block’s tables is used once: one multiply and one add, so two sums. That is about 14 billion sums, plus 1 billion for the final scores public.

Comparing the new token with 1,000 earlier ones adds about 0.5 billion, also multiply-and-add. The norms, bends, softmax and additions to the running list come to roughly 8 million, about 0.05% example. So a pass is almost entirely grid multiplies, the job GPUs are built for (Part 5, chapter 10). Part 8 shows why fetching these 8 billion numbers from memory, not the sums, is the real cost.

Go deeper: the rule of thumb, and where it comes from

A 2020 scaling study gives the forward pass as about 2 × N + 2 × layers × context × width sums, where N is the learned numbers in the blocks public. Its second term averages over every position in a training text; for one new token at position n the comparisons cost 4 × layers × n × width, which is what this page uses. The word table is only looked up, so for Llama 3 8B the total is about 15 billion rather than the 16 billion of “two sums per learned number” in Part 5. The 8 million is a rough count of the other steps, made for this page.

Try it

Build a model, count its numbers

Design your own transformer with GPT-2’s recipe: feed-forward four times as wide as the list, one word table used at both ends, a 1,024-row position table public. Pick the width, the number of blocks, the size of the token list, and how many tokens of text the newest token looks back over. The bars show the sums needed to write one token.

Three things to notice. Feed-forward always costs twice attention’s tables. Doubling the width roughly quadruples the blocks’ cost, while doubling the blocks only doubles it: “Twice as wide” at 12 blocks costs the same in the blocks as GPT-2 small at 48 (slide it and see), but its word table doubles. And comparisons stay tiny until the text gets long, which is where Part 14 picks up.

Go deeper: exactly what the lab computes

Width d, blocks L, token list V, text n. Learned numbers: V × d (word table) + 1,024 × d (positions) + L × (12d² + 13d) (tables, biases and norms in each block) + 2d (final norm). Sums for one token: 2 × 4d² × L (attention tables) + 2 × 8d² × L (feed-forward tables) + 4 × L × n × d (comparisons) + 2 × V × d (final scores). Biases, norms and bends are left out of the sums because they are small. The dashed line is two sums per learned number, the rule from Part 3. With the GPT-2 small preset the count is exactly 124,439,808 public.

The surprise

All the tokens climb at once

Reading your prompt is not done word by word. All its lists climb the stack together, and each block handles every position in one big grid multiply: a grid of six lists times a table. Only writing goes one token at a time (Part 2, chapter 12).

While writing, each new list climbs alone, and its attention reads the keys and values saved from the tokens before (the KV cache, Part 7, chapter 15). This is why an answer starts after a pause and then streams out steadily. The bonus study, Inside LLM serving, is built around this difference.

Where it came from

From the 2017 design to today

The 2017 Transformer was built for translation, with two halves: an encoder reading the source sentence and a decoder writing the translation, six blocks each, 65 million numbers public. Chatbot models keep only the writing half, with the look-backwards-only rule from Part 7.

Since then the block has changed only in details: the norm moved to the front of each step (GPT-2) public, then RMSNorm, SwiGLU and RoPE (Llama) public. What changed enormously is the size, by a factor of about 6,000 in seven years. Note the scale: each dashed line is ten times the one below.

The words, in plain language

TransformerThe model design: blocks of attention and feed-forward around a running list.
Forward passOne trip of the lists from the word table to the final scores.
Block (layer)One attention step plus one feed-forward step, each added to the running list.
Residual streamA token’s running list, which every step adds a note to.
Feed-forward (MLP)Widen, bend, narrow: a small network applied to each token alone.
Layer normRescaling a list to a standard size before each step. RMSNorm is a simpler version.
Residual connectionThe “+” shortcut that adds a step’s result instead of replacing the list.
Width (model dimension)How many numbers are in each token’s list: 768, 4,096, 16,384.
Output table (unembedding)One row per token, used to score every possible next token.
ParametersAll the learned numbers in all the tables.

So what

Next: chips built for this one pass

A forward pass is a long, fixed sequence of grid multiplies, the same for every token and every question, with almost nothing else mixed in. That makes it a tempting target for chips that drop everything except grid multiplies and fast memory. Part 10, on the chip track, compares GPUs with Google’s TPUs and Amazon’s Trainium: what each design removes or adds to get better at exactly this pass.

AN IDEA TO TAKE WITH YOU
A transformer is one block, attention then feed-forward, each adding a note to every token’s running list, stacked dozens of times: a tower of multiplications that ends in one guess.
